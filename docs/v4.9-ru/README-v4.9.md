# «Захвати рынок или закрой бизнес» — v4.9

> **Архив.** С версии 5.0 игра называется только **Market Game**: прежнее
> название несло агрессивный оттенок. В файлах этой папки оно оставлено как
> часть истории версии 4.9 — на сайте и в новых материалах его нет.

Полный резервный комплект. Из этих файлов игра разворачивается с нуля на
пустом проекте Supabase и пустом репозитории GitHub, без обращения к
чему-либо ещё.

```
sql/            запросы к базе, запускать по порядку
functions/game/ код Edge Function
web/            файлы для GitHub Pages
docs/           материалы для участников и описание игры
tests/          проверки, которые стоит прогонять после правок
```

Проверено на чистой базе PostgreSQL 16: установка проходит без ошибок,
повторный запуск любого файла безопасен, экономический движок сходится с
эталоном на 400 сценариях.

---

## Что понадобится

- Аккаунт Supabase (бесплатного плана хватает для обкатки)
- Аккаунт GitHub с публичным репозиторием
- Бот в Telegram (создаётся у @BotFather)

---

## Шаг 1. Проект Supabase

1. `supabase.com` → **New project**.
2. **Регион** выбирайте ближайший к географическому центру ваших игроков.
   Потом он не меняется — придётся пересоздавать проект.
3. Пароль базы сохраните сразу, он показывается один раз.
4. Project Settings → **API Keys**. Выпишите:
   - **Project URL** — вида `https://xxxx.supabase.co`
   - **publishable** (в старых проектах `anon`) — публичный, поедет в браузер
   - **secret** (`service_role`) — секретный, в браузер не попадает никогда

При создании проекта полезно включить опцию автоматического RLS на новых
таблицах. Схема и так включает его явно, но лишняя страховка не мешает.

---

## Шаг 2. База

SQL Editor → **New query** → вставить файл целиком → **Run**.
По порядку:

| Файл | Что делает |
|---|---|
| `01_schema.sql` | 12 таблиц, индексы, RLS, базовый пресет экономики |
| `02_functions.sql` | создание партии, штрафы и субсидии, определение роли |
| `03_apply_round.sql` | **пропустить** — целиком вытеснен файлом 04 |
| `04_treasury.sql` | казна и расчёт месяца одной транзакцией |
| `05_reset.sql` | обнуление партии |
| `06_rating.sql` | рейтинг по лигам, таблица зачётов обучения |
| `07_restart.sql` | архив партий и перезапуск |
| `08_training_credits.sql` | зачёт обучения игрокам, игравшим до перехода на базу |

**Перед запуском `02_functions.sql`** замените в конце файла ник ведущего
и список игроков — там помечено. Ник пишется строчными буквами без
собачки.

**Перед запуском `08_training_credits.sql`** замените список ников на свой
или удалите строки, если зачитывать обучение некому.

После установки в базе должно быть 14 таблиц, у всех включён RLS.

Файлы `98_rating.sql` и `99_diagnostics.sql` устанавливать не нужно — это
готовые запросы для разбора партий, запускаются по мере надобности.

## Шаг 3. Edge Function

Edge Functions → **Create function** → имя **`game`**.

- В `index.ts` вставить содержимое `functions/game/index.ts`
- **+ Add File** → назвать `economy.ts` → вставить `functions/game/economy.ts`

Secrets → добавить `GAME_CODE` со значением `TEST-01` (или другим кодом
серии). Если секрета нет, функция подставит `TEST-01` сама.

**Deploy function.**

Проверка: панель **Test**, метод **GET**, тело очистить, параметры
`action=monitor` и `u=ваш_ник`. Должен вернуться список игроков.

---

## Шаг 4. Веб-клиент

В `web/App.js` (строки 8–9) и `web/tablo.js` (строки 6–7) подставить свои
значения:

```js
var EXEC_URL = 'https://ВАШ-ПРОЕКТ.supabase.co/functions/v1/game';
var SUPABASE_KEY = 'ваш publishable ключ';
```

Загрузить все шесть файлов из `web/` в репозиторий. Settings → **Pages** →
Deploy from a branch, ветка `main`, папка `/ (root)`.

Публикация занимает 2–3 минуты. Проверка в браузере:

```
https://ваш-логин.github.io/репозиторий/index.html?u=ваш_ник
```

Должен открыться пульт ведущего.

## Как вести сессию

1. Пульт ведущего → **Состав партии** → вписать ники → Сохранить
2. При необходимости → **Настройки партии** → правки → Сохранить
   (действуют со следующего открытого месяца)
3. **Открыть месяц** → игроки подают решения → **Рассчитать месяц**
4. Повторять до 12, 24 или 36 месяца
5. **Завершить партию и начать новую**

Штрафы и субсидии — блок **Государство**, в любой момент, любому игроку
независимо от его статуса.

Табло для проектора: `.../tablo.html`

**Режим ведущего.** Адрес `?u=ваш_ник&as=ник_игрока` открывает чужой
кабинет с полными правами: посмотреть, что происходит у игрока, или
отыграть за него при обкатке в одиночку. Работает только в браузере —
в Telegram адрес фиксированный. Обычному игроку параметр бесполезен.

---

## Что важно понимать про перезапуск

Кнопка «Завершить партию и начать новую» **не стирает партию**. Она
закрывает текущую, отправляет в архив и создаёт рядом новую с тем же
составом и настройками. Коды идут как `TEST-01`, `TEST-01#2`, `TEST-01#3`.

Без этого рейтинг по всем партиям был бы невозможен: каждый сброс затирал
бы предыдущую игру.

`GAME_CODE` задаёт **серию**, а не конкретную партию — менять его при
перезапуске не нужно, функция сама находит самую свежую.

Если сыгранных месяцев не было, партия просто обнуляется на месте: пустые
записи от случайных нажатий в базе не копятся.

## Обслуживание

**Автопауза.** На бесплатном плане проект засыпает после семи дней без
запросов. Разбудить может только владелец из панели, кнопкой Restore, за
одну-три минуты. Откройте пульт за полчаса до сессии.

**Бэкапы.** На бесплатном плане их нет. К первой сессии с людьми,
пришедшими по расписанию, стоит перейти на Pro: там ежедневные бэкапы и
нет автопаузы.

**Кэш Telegram.** Ссылки на скрипты помечены версией (`?v=49`). При
обновлении клиента поднимайте цифру в `index.html` и `tablo.html`, иначе
WebView отдаст старые файлы. Это самая частая причина «я всё залил, а
ничего не изменилось».

## Правила работы с кодом

**Экономика живёт в `economy.ts`.** Это чистая функция без обращений к
базе, сети и времени. Только поэтому её можно проверять золотыми тестами.
Меняете формулы — правите этот файл и прогоняете `tests/golden.mjs`.

**Учёт живёт в SQL и `index.ts`.** Куда пошли деньги, что записать, что
показать — это не экономика. Правки там движок не трогают, и тесты
остаются в силе.

Именно это разделение позволило добавить казну, не притрагиваясь к
расчёту месяца.

**Клиент к базе не ходит.** RLS включён на всех таблицах без единой
политики, то есть публичный ключ не может ничего. Вся работа идёт через
Edge Function с секретным ключом. Это снимает главный риск утечки и
заодно не даёт игрокам увидеть решения соперников.

## Проверки после правок

```bash
node tests/golden.mjs        # экономика: 400 сценариев против эталона
node tests/reset_check.mjs   # ни одна таблица не забыта при сбросе
```

`golden.mjs` требует, чтобы `economy.ts` был скомпилирован в
`build/economy.mjs` — например через `esbuild economy.ts --format=esm
--outfile=build/economy.mjs`.

Для разбора расхождений в партии — `sql/99_diagnostics.sql`. Начинать с
первого запроса: он сверяет кассу каждого игрока с журналом движений.
Нули в колонке расхождения означают, что деньги никуда не терялись, и
разбираться надо не в экономике, а в действиях игроков.
